## Context

`refresh_compile_jobs` reads `compile.at` and `compile.timezone` and quietly schedules nothing when they are absent or unreadable. `SetBrainCompiler` is the model for a shared brain setting: a config batch built from `config_on_main`, human-only. Compile and routing call `resolve_job(None, …)`, so a Space's row for either never runs, but `ModelSelection::for_space` merges every override into the table it reports.

## Decisions

- **One reading of a compile.** `compile_schedule(&BrainCompile) -> Result<Schedule>` in `compile.rs` replaces the inline parse. `refresh_compile_jobs` takes `.ok()`, and Set up and `set_brain_compile_time` propagate the error, so what is accepted is exactly what is scheduled. Keeping the existing leniency (`6:00` parses) means no brain that compiles today stops compiling.
- **`compile` keeps its unknown keys.** `set_brain_compile_time` writes `config["compile"]["at"]` and `["timezone"]` rather than replacing the object, as `update_brain_gate` does for `gate`. A `compile` of the wrong type already makes the config unreadable, so `config_on_main` refuses it. Asking for the time already on `main` is refused, since the batch would change nothing.
- **`set_up_brain` takes a required `compile`.** Every client is the app, which ships with its host for This Mac, and a Mac driving a paired host of another version already has refused commands. A defaulted field would bring back a Set up with no schedule.
- **The host names its timezone.** `BrainsPage.this_timezone` is `jobs::local_timezone()` of the host the page drives, since Set up makes that host the compiler. It is optional in the reply, so an older host reads as UTC in the form, which stays editable.
- **The timezone is a searchable Select,** as New project's choices are, over `chrono_tz::TZ_VARIANTS`, which also holds the older link names, so any zone the schedule can read is listed. The study draws a dropdown, and 600 names need search.
- **`Job::space_may_set` is the rule's one statement.** `validate_space_rows(rows, saved)` refuses a Router or Compiler row that `saved` does not hold, then keeps the table's rules for the rest. It leaves unchanged old rows out of the rules check, because such a row may also break the table's rules and must not block a save. `set_space_model_settings`, `check_space_models` and the Models page's draft error all call it. `check_space_models` covers every other command, because `update_space` is the only one that changes a Space's rows.
- **`overrides()` still returns every row; `for_space` drops the two jobs.** The page's draft and `SpaceModelSettings` must carry old rows so an unrelated save writes them back and Remove them can drop them through the normal draft and Save. Dropping in `for_space` means every resolver, the fallback banner and model reasons ignore them with no change at their call sites. `SpaceModels::ignored` lists them for the note.
- **The note lives on the two pages that show a Space's rows.** The Models banner offers Remove them, and the Space page's link line says the same in words, with its row count leaving them out. Effective settings has no place for a row it does not list. `SpaceLocal.notes` is not used: those are written once when joining, and these rows can arrive by sync at any time.
- **`workspace_context` drops the Compiler row with the Router row.** With `for_space` it no longer carries a Space's row, and no coordinator starts a compile, so it would be noise.
- **Scrolling to a card uses GPUI's `ScrollAnchor`,** which works for an element that is not a direct child of the scrolled one. `ui::page` takes an optional `PageScroll`. A request waits for the page's next render, because an anchor has no position until it has been painted, and the page notifies after the scroll so the cached view repaints at the new offset. Repositories opens at the top by resetting the offset.
- **Which sentences an additions line can match.** At a Space or repository additions reach every role, so a line matches any Behavior. At the Workspace they are one skill's rules, so a line matches that skill's Behaviors only, and a rewritten skill offers nothing, as its rules are not in effect. Any choice's sentence counts, not just the one in effect: the study's point is that a line left in place outlives turning the Behavior off.
- **Keep it is remembered on this Mac,** in `Preferences`, by scope, skill and normalized line, like the Space page's one-time note. It is not a setting and does not need to reach a teammate, who may make a different choice.
- **One offer at a time.** The banner counts the lines and quotes the first, so several lines do not stack banners over the role sections. Delete removes every line equal to it, in the saved text and in the editor, so an unsaved draft can neither restore it nor stop following the save.

## Risks / Trade-offs

- **A second config PR can be opened while one is open,** as Change compiler already allows. The two conflict on GitHub and the human settles it there. The PR gate on the same page shows both.
- **`next_compile` prints a time from the file even if it cannot be scheduled.** This is existing behaviour of a hand-edited file, and Change compile time fixes it.
