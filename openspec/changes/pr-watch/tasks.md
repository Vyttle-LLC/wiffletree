## 2. Watcher host module

- [ ] 2.1 Add `runtime::gh_output(path, args)`, built on `bounded_output` with a 30 s deadline, `GH_PROMPT_DISABLED=1` and `NO_COLOR=1`, which reports `gh`'s last error line on failure. Verify with a unit test that a missing binary and a non-zero exit become errors naming the cause.
- [ ] 2.2 Create `workspace-host/src/pr_watch.rs` with the GraphQL query (branches passed only as `$hN` variables, at most 50 per call), `github_repository(remote_url)` for HTTPS and SSH `github.com` URLs, and `parse(json, tickets)`. The parser skips cross-repository PRs, prefers open over newest, maps the rollup and merge states, counts unresolved threads, and takes the largest id among the last issue comment, the last review and each thread's last comment. Verify with recorded JSON in PR #31's shape, a new reply inside an existing unresolved thread that changes `last_comment_id` with nothing else changed, a fork PR, open-versus-newer-closed, a null rollup, an unknown enum value, and non-GitHub and malformed remotes.
- [ ] 2.3 Add `pr_watch::fetch(query)`. It resolves owner and name from the base's remote, makes no call for a non-GitHub repository, runs `gh api graphql`, reads the worktree HEAD for merged PRs, and returns the results with `rateLimit`. Verify the non-GitHub path makes no `gh` call, and that a fake `gh` on `PATH` in a test returns parsed results.
- [ ] 2.4 Add `pr_watch::Watch`, which holds each repository's due time, running mark and failure count. It covers the first pass at once, 60 s active, 5 min idle, a 5/10/20/30-minute backoff, the wait for `resetAt` below 200 points, dropping repositories without open tickets, and `next_due()`. Verify each rule with explicit times.
- [ ] 2.5 Add `Host::pull_request_queries()`, which lists repositories with open tickets whose coordinator isn't archived, and `Host::record_pull_requests(repository, outcome)`. The latter reloads each ticket, skips closed ones, keeps the stored merge state on `Unknown`, and saves and logs a `pull_request` event only on change. It also updates the in-memory `pull_request_checks` and keeps snapshots on failure, and `snapshot()` exposes the checks. Verify the spec scenarios "Change recorded once", "Unknown merge state", "Failed pass" and "Coordinator reads the PR".
- [ ] 2.6 In `service.rs`, add the `pr_watch` field on `Actor`, `Event::PullRequests`, and `Actor::refresh_pull_requests(now)`. Call it from `process` after `refresh_overlaps`. Spawn panic-safe threads like `spawn_overlap_check`, and arm `wake(next_due)`. Handling the event clears the running mark, updates `Watch` and signals only on change. Verify with actor tests beside the overlap tests: one pass per repository at a time, a panicking fetch frees the repository, the next wake is armed on a quiet host, and an unchanged result sends no signal.
