Last and next run, Run now and the history live on the brain's card. Run now says why it waits: a run in progress or an open compile PR. The history pages by six and shows each run's trigger (Scheduled, Catch-up, Run now, Ruling), counts, model, outcome, PR, usage and procedure version. A run with nothing pending reads “No pending entries · no model call”. A failed or timed-out run names its reason and leaves the cursor unchanged. The compile PR travels the PR gate as a “Compile run” batch, like any other. A conflict that touches no project's repository appears here instead of an Inbox.

One card per conflict, in every project whose Space names the brain and whose repositories include the claim's. Watch onboarding shows c-7b21 too, and a ruling here clears it there. The card puts what each side says next to each other, with verification and authors as evidence, and marks the recommended ruling. Keep both opens a one-line field that scopes both. Defer writes nothing. Every other ruling writes a decision entry by you and opens its batch at once. Only you rule: agents see no ruling tool, and the compile session can only queue.

Compiles are billed to their brain, not a project. Each brain gets its own line, “Brain compile · ‹brain›”, next to coordinators and threads. Runs skipped with nothing pending cost nothing and are counted only in the hint. Selecting a line opens that brain's run history. The cost by model table below is unchanged.

How it behaves

  • Only the Mac named in wiffletree-brain.json compiles a brain, nightly at its time, once on wake after a missed time, on Run now and when a ruling merges.
  • At most one run and one open compile PR per brain. A brain's main is never pushed: every compile is a PR through the brain gate.
  • The compile session changes only notes/**, STATUS.md and reconcile-queue.md, has only queue_conflict and finish_compile, and stops after 30 minutes.
  • Rulings are yours alone. Uphold existing, Keep new and Keep both write a decision entry; Defer writes nothing.
  • This study is static and pending Michael's approval. It is not the GPUI implementation.
