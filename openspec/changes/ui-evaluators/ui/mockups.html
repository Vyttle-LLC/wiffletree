Wiffletree · UI evaluators study

Evaluators that drive the screen, only when you allow it

A coordinator can start a UI evaluator: a fresh, blind agent on one exact model that gets only a prompt and a run folder, drives an app, and writes a report there. There are two modes. App only drives just the app under test, through its automation socket. Full desktop uses Claude's or Codex's own computer use and can reach any app.

Approved by Michael, 2026-11-04
  • Off by default. The first time a coordinator asks, you choose a mode for that project (screen 1). Each later full-desktop run still waits for you to press Start (screen 3).
  • Blind. An evaluator has no repository, shell, brain, history, memory, or any of your CLAUDE.md, settings, skills or MCP servers. It reads its prompt and writes only to its run folder. The coordinator gets the run's state and folder, never the transcript.
  • Pinned model. A run names its provider, model and effort and never falls back. At a usage limit it waits for the reset, and says so (screen 4).
  • Recommendations to confirm: app-only runs may run side by side, since each drives its own copy of the app. Full-desktop runs go one at a time, through one queue shared by every project.

Out of scope for this change
  • Sending a message to a running evaluator. It runs one prompt to the end.
  • An editable list of apps a full-desktop run may never open. Instead, Wiffletree approves only the apps the run names when Claude asks for app access.
  • Evaluators on a paired remote Mac.
