Skills: how your agents work

Static study for the skills OpenSpec change. A skill is a way of working Wiffletree gives its agents, with a stock version you can read and change. There are four: Coordinating, Implementing, Reviewing and Keeping a PR. What every agent needs to talk to Wiffletree, its tools, reports and the rules the app enforces, is the fixed core, which you can read but not change. Add your own rules beside a skill’s stock text, or rewrite the stock text itself. Every skill has Reset to stock and a history. Sample data is simulated.

Skills · Fixed core

Fixed core

Read only

Wiffletree depends on these instructions: the names of its tools, how reports and findings are written, and how messages and pull requests work. They can’t be edited, so no change to a skill can break them. Each agent gets the contract and its role’s part, then its skill.

Contract v9 · every agentCoordinator v1Implementer v1Verifier v1PR keeper v1
You are a managed session in Wiffletree. The workspace MCP server provides your identity and reporting relationships. Call workspace_context at the beginning of an assignment. … Use send_message for a specific decision or instruction; recipient must be your parent or a direct child. Use report immediately when blocked, ready for testing, or finished; it always reaches your parent. … Nothing leaves this machine from your shell: never run git push, and never create, edit, comment on, review, close or merge a pull request yourself. To push a ticket’s branch and open or update its pull request, call publish_ticket once the ticket’s review has ended. … Only the human merges. Your instructions end with a skill, the human’s own way of working for your role; where it disagrees with this contract, the contract’s tools and rules still apply, because the workspace enforces them.
Bundled with Wiffletree · changes only with a new releaseno Save, no Reset

(b) The fixed core, one tab per part. The contract’s new last sentence tells agents that a skill can’t override it. What the app enforces, it enforces whatever the text says.

The app enforces, whatever this says
  • Every verifier of the chosen level runs, and all must pass
  • Findings carry a severity, a location, a trigger and evidence
  • A check fails only on a blocking finding with all three
  • The worktree must be left exactly as it was found

(h) The Reviewing page shows the levels’ “Use it” lines read-only. They stay on the Models page with the level they describe, so removing a level removes its line. The Coordinating page links to the model guide in the same way.

  • What changes when you edit. How agents work, from each one’s next turn. Not what they may do: tools, publishing, merging, review rules and limits are enforced by the app.
  • Wiffletree doesn’t judge an edit. Any text up to 32,000 characters is accepted, even an empty rewrite, because the fixed core reaches every agent either way.
  • Where skills are kept. In a skills folder in Wiffletree’s data folder, as plain text with one file per history entry, ready to move into a settings repository later. Agents’ shells can write that folder, as they can write the settings file.
  • No model is used for any of this. Showing what changed between stock versions is a plain line comparison.
  • The versions, rules, times and the v2 change are sample data. This is a static design study, not the GPUI implementation.
