Design study · Skill updates

Updates that reach your rewrite

Static study for the skill-updates OpenSpec change. When a Wiffletree update changes the stock text of a skill you rewrote, Wiffletree now brings the change into your rewrite for you. Changes that don’t touch what you changed merge as plain text. Where you both changed the same passage, the PR keeper’s model merges just that passage. You’re asked only when the two wordings want different things. Every merge leaves a note you can review or undo. Sample data is simulated: no model ran and nothing was merged.

(g) Undo asks first and says it is exact. The merge’s history entry keeps your text and base from before the merge, so Undo writes those bytes back rather than rebuilding them. After you’ve saved again, the entry still offers Undo this merge, which asks first and says your later changes stay in the history. A merge, an Undo and a question are history entries like any other change, so they sync with the skill.

  • Only rewrites are merged. Your own rules sit beside the stock text, so an update never needs merging into them. The fixed core is never merged.
  • Overlap is by paragraph. The merge compares paragraphs, which blank lines separate. The title line with the version is merged on its own and never overlaps, so a new version number never sends your first paragraph to the model. A change from the update and one of yours overlap when they touch the same paragraph or neighbouring ones, so a blank line never keeps two changes apart. The plain merge uses the diff library Wiffletree already has, with no new one.
  • The model. The PR keeper’s model, when it is a Claude model, with every tool off and only the skill’s texts as input. It runs at most once per skill per update across your Macs, unless two Macs merge at the same moment, and only for the passages you both changed.
  • Your Macs merge once. At launch a Mac waits for its first sync before merging, so it usually takes another Mac’s merge. If two merge at once, the first to reach GitHub wins, and the other takes it without pausing the skill.
  • The versions, texts, times, model and token counts are sample data. This is a static design study, not the GPUI implementation, and nothing here ran a model or a Git operation.
