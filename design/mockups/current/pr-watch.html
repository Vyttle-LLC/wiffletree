Pull request status on tickets and repositories

Static study for the pr-watch OpenSpec change. The host polls GitHub for each open ticket’s PR without a model. It shows (a) the PR on the ticket row, (b) the open-PR count on the repository row, and (c) the ticket card and the message the coordinator gets when a PR merges. Sample data is simulated.

(c) The Team panel’s ticket card names the PR, its head and when it was checked, with a link to GitHub. When the PR merges, the coordinator gets one message from Wiffletree, never in the human’s name. It says whether the merged head is the ticket worktree’s HEAD, which accept_ticket checks against the verified commit. The snapshot also rides on the ticket in workspace_context. No PR title, body or comment text is ever copied into a message.

  • The host makes one read-only gh api graphql call per repository per pass: about every 60 s while the repository has an open PR, every 5 min otherwise, and backing off after failures. It never comments, labels, pushes, rebases or merges.
  • Settled after this study (see design.md, “Settled by the human”). Failed checks and conflicts wake only the coordinator, without PR text, at most once per head and 3 times per PR, then one “budget used” message. A PR closed without merging sends one message. New comments wake nobody; that is deferred to a later change. These messages are not drawn here.
  • This is a static design study, not the GPUI implementation.
