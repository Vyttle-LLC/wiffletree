Design study · Settings as a modal

Settings opens over the main window, so nothing it shows can hide behind it.

Today Settings is its own window (900 × 820). Pairing a device from Settings › Remote access let the main window cover it, so the code was never seen. This study moves the same Settings, with the same sidebar and sections, into a modal over the main window, as Connect a computer already is. New or changed parts have a red edge. Items marked Decide are the choices to approve.

Confirmations stay inside Settings, over its body as they are today. Esc or clicking outside the confirmation closes only the confirmation, never Settings with it.

How it closes

  • ✕ in the modal's header.
  • Esc, unless a confirmation or menu is open on top: then Esc closes only that.
  • Clicking the dimmed main window. Decide Recommended yes, like Connect a computer. The risk is losing a half-typed field, such as a repository name; settings save as you change them, so nothing saved is lost.
  • ⌘, while Settings is open does nothing (it is already in front). Decide or toggle it closed.

Pairing when Settings closes

  • Closing Settings while a code is showing cancels that pairing, so no code stays live that nobody can see. Decide or leave it valid until its 2 minutes run out.
  • Remote access keeps looking for changes only while Settings is open, as today.

When the main window is closed

  • Settings needs a window to sit over. ⌘, or Wiffletree › Settings… with no main window opens the main window first, then Settings over it.
  • There is never a second Settings: one per main window, and ⌘, focuses the open one.

Unchanged

  • Every section, setting and wording; the sidebar's groups and order (except Builds and Remote access split in two).
  • Settings follows the host the switcher selected. The switcher sits behind the modal, so to change host you close Settings first.
  • Light and dark follow the app's theme.
