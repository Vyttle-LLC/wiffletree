Settings › Disk. One page for the whole machine, because the disk is shared across Spaces. Tickets are grouped by project, largest first inside a group. A row's small line names where the space is when it is outside target/-style folders (Xcode DerivedData, the ticket's scratch folder) or why something was left alone. Sizes refresh in the background, at most every few minutes.

Notices and Inbox. Reclaims are quiet notices in the project's chat and fold like the PR watcher's. Only the hard floor and a failing delete reach the Inbox, because only those need you.

How it behaves
  1. Build output is what the detector finds: ecosystem defaults, CACHEDIR.TAG folders, a repository's committed .wiffletree/build-output, the worktree's Xcode DerivedData, and the ticket's scratch folder. Folders it is unsure of are never reclaimed and are named on the row.
  2. Reclaiming deletes build output and keeps source, uncommitted changes and untracked files. It never touches a ticket with a build in progress or an agent in a turn.
  3. Order: accepted or closed tickets first, then idle ones, least recently used first.
  4. Removing a ticket deletes its worktree, its DerivedData and its scratch folder together.
Questions for you (my recommendation first)
  1. Where: a Settings › Disk page plus a line in the Agents panel (recommended), or the Agents panel only?
  2. Manual Reclaim buttons: keep them (recommended), or make reclaiming fully automatic?
  3. Hard-floor card: offer "Reclaim all but running builds", which also reclaims recently used tickets (recommended), or only point to Settings › Disk?
