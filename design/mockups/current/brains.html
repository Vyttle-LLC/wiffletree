Design study · Second brain

Brains: a team-shared, PR-gated memory

Interactive study for bringing the Git-backed second brain into Wiffletree. Start on Workspace › Brains, open a brain, or select the Watch app call relay project and use its Memory and Inbox panels. Press ⌘K anywhere to search. Every brain, entry, commit, PR, person and time is simulated; nothing here reads Git, GitHub or a provider.

Decided by Michael on October 29, 2026, when he approved this mockup
  1. Where the browser lives. One workspace Brain page, filtered by project. A project's Memory panel is the summary that opens it; there is no separate project Brain destination.
  2. Fixing a failed check. Amending an unmerged batch is fine, either by redacting the line or by adding an inline allow marker. Entries become append-only once merged.
  3. Ruling path. A ruling writes a decision entry and starts a compile right away.
  4. Ruling names. "Uphold existing", "Keep new", "Keep both" and "Defer" stay as drawn.
  5. Personal and unowned repositories. They default to no brain.
  6. Teammates' entries. Author plus PR is enough for entries the skill writes.
  7. Search reach. Search never spans organizations: one brain at a time, scoped to a project or the whole brain.
  8. Compiler host. It can be changed from this page, but it is stored in a config file in the brain repository and changed through a PR, so every install agrees.
Theme Search: ⌘K · Ctrl K · /
  • The PR gate. Each log batch (one per ticket or session) and each compile run becomes one PR in the brain repository that auto-merges when its six checks pass: gitleaks, sensitive-information scan, markdownlint, wikilinks, log schema and size, and path ownership. A failed check pauses auto-merge and raises one Inbox item on the project that wrote the batch. The scan reports file and line, never the matched value.
  • Who sees what. Every install logs; only the brain's compiler host (here Michael's Mac) compiles. RB and Oscar log through the skill and read the brain on GitHub or in their own Wiffletree.
  • Verification. verified: the commit, merged PR or tag exists in a known repository. claimed: the entry names an anchor that is not merged yet. unverified: no anchor. A commit verifies the Git anchor, not every word of the claim.
  • This is an HTML study, not the GPUI implementation. Ruling, redacting and remapping change only this page's state and reset on reload.
