Design study · Settings repository

Your settings on every Mac

Static study for the settings-repository OpenSpec change. Name a private GitHub repository in Settings, and Wiffletree keeps your skills, review levels, model guide, check-ins and PR keeper triggers in sync between your machines. It pulls at launch and every 5 minutes, and pushes a few seconds after you change something. What belongs to one machine, such as its providers and models, its workspace folder and the owners it allows, stays on that machine. When two machines change the same setting, that one setting pauses until you choose. Machines, times and changes are simulated.

(d) A paused setting raises one workspace note. It sits at the top of every project’s Inbox, because it belongs to no project, and settling it once clears it everywhere. Compare is open on the first note. Two Macs changed the same file, so only that file waits. The second note is a file changed outside the app. It doesn’t spread to your other Macs’ agents until you’ve seen it. The third arrived in a form this Mac can’t use, so this Mac keeps its own until the other Mac fixes it or you keep this one.

(e) After joining, the section lists what this Mac still needs. A shared setting this Mac can’t run is held off here and never rewritten: your other Mac keeps it on, and the trigger starts here once this Mac has a keeper model. Rebasing needs no model, so it runs.

  • A new kind of push. Choosing the repository on a Mac is what lets Wiffletree push to it: only its main branch, only Wiffletree’s own files, never by force. The owners you allow for pull requests neither grant it nor are needed for it.
  • Who can change your agents. Skills are part of every agent’s instructions, so whoever can push to this repository can change how your agents work on every Mac. A private repository under your own account keeps that to you.
  • Agents’ shells. They aren’t sandboxed. They can write the shared folder and could push to the repository with your credentials. Sync pauses an edit it didn’t make, so it doesn’t spread through sync, but it can’t stop a shell from pushing.
  • No model is used for any of this. Sync is Git and whole-file comparisons.
  • Machine names, times, rules and errors are sample data. This is a static design study, not the GPUI implementation, and nothing here runs Git.
